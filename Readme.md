# PROMPT: สร้าง AI Smart Home Dashboard สไตล์ JARVIS / Sci-Fi

คุณคือ Senior UX/UI Designer, Creative Frontend Developer และ AI System Architect ที่เชี่ยวชาญการสร้าง Dashboard ระดับ Premium สำหรับระบบ AI และ Smart Home

ผมต้องการสร้าง Web Application สำหรับโครงงานมหาวิทยาลัยชื่อ **AI Smart Home Assistant** โดยมีแนวคิดคล้าย JARVIS จาก Iron Man ให้ผู้ใช้สามารถพูดคุยกับ AI สั่งเปิด–ปิดไฟ ปรับความสว่าง และควบคุมอุปกรณ์ภายในบ้านผ่านคอมพิวเตอร์และโทรศัพท์มือถือ

**ข้อสำคัญ: ตอนนี้ยังไม่ต้องเขียนโค้ด ให้เริ่มจากการวิเคราะห์และออกแบบ UX/UI ก่อน**

## 1. วิเคราะห์วิดีโออ้างอิง

ใช้คลิปวิดีโอที่ผมแนบมาเป็น Reference หลัก

วิเคราะห์องค์ประกอบที่มองเห็นได้ ได้แก่
- โครงสร้างและตำแหน่งของแต่ละ Panel
- วงแหวน AI หรือ Central Visualizer
- สีพื้นหลัง สีหลัก สีรอง และแสงเรือง
- เส้นกรอบ เส้นข้อมูล และองค์ประกอบแบบ HUD
- รูปแบบกราฟ คลื่นเสียง ตัวเลข และข้อมูลสถานะ
- แอนิเมชัน การเปลี่ยนสถานะ และการเปลี่ยนหน้าจอ
- สัดส่วนขององค์ประกอบและลำดับความสำคัญในการมองเห็น

แยกให้ชัดเจนว่าส่วนไหนควรอ้างอิงจากคลิป ส่วนไหนควรปรับให้เหมาะกับ Smart Home และส่วนไหนเป็นฟังก์ชันที่ต้องออกแบบเพิ่มเติม

อย่าคิดว่าคลิปมีฟังก์ชันที่มองไม่เห็น หากข้อมูลไม่เพียงพอ ให้ระบุว่าเป็นข้อเสนอการออกแบบ

## 2. Design Direction

ออกแบบให้เป็นส่วนผสมระหว่าง

- Futuristic Sci-Fi Interface
- JARVIS-inspired AI Control Center
- Premium Smart Home Dashboard
- Modern Minimal UI ที่ใช้งานได้จริง

แนวทางด้านภาพ:
- พื้นหลัง Dark Navy หรือ Near Black
- สีหลัก Cyan / Electric Blue
- ใช้แสง Glow, Gradient, Glassmorphism และเส้น HUD อย่างมีระดับ
- ใช้วงแหวนหลายชั้น เส้นวงโคจร และจุดแสงที่เคลื่อนไหว
- ใช้ Typography ที่อ่านง่ายทั้งภาษาไทยและภาษาอังกฤษ
- จัดลำดับข้อมูลให้ชัดเจน ไม่ทำให้ทุกองค์ประกอบแย่งความสนใจ
- หลีกเลี่ยงการใช้ Neon มากเกินไปจนอ่านยาก
- ออกแบบให้ดูเหมือนผลิตภัณฑ์ที่ใช้งานได้จริง ไม่ใช่เพียงภาพ Concept

ต้องการแอนิเมชันหลายชั้นที่ดูมีชีวิตชีวา แต่ยังลื่นไหลและควบคุมประสิทธิภาพได้

## 3. โครงสร้างหน้าจอ Desktop

ออกแบบหน้า Dashboard หลักโดยพิจารณาองค์ประกอบดังนี้

### A. Top System Bar
แสดง:
- ชื่อระบบและโลโก้
- วันที่และเวลาปัจจุบัน
- สถานะ AI
- สถานะ Backend และ MCP
- สถานะการเชื่อมต่อ Arduino UNO Q
- การแจ้งเตือนและการตั้งค่า

สถานะทั้งหมดต้องรองรับข้อมูลจริงในอนาคต ไม่ควรแสดงว่า Connected หากยังไม่ได้เชื่อมต่อจริง

### B. Sidebar Navigation
ประกอบด้วยเมนู:
- Dashboard
- Devices
- AI Assistant
- Activity Logs
- Automation
- System Settings

ออกแบบ Active State, Hover State, Tooltip และการยุบเมนูให้เหมาะกับ Desktop

### C. Central AI Core
เป็นจุดเด่นที่สุดของ Dashboard

ออกแบบวงแหวน AI หลายชั้น โดยอาจประกอบด้วย:
- Outer Orbit Rings
- Rotating Segments
- Pulsing Glow
- Audio Waveform
- Particle Effects
- Energy Core
- Status Label
- Listening / Thinking / Executing / Speaking Indicators

วงแหวนต้องเปลี่ยนพฤติกรรมตามสถานะของระบบจริง ไม่ใช่เล่นแอนิเมชันแบบเดิมตลอดเวลา

### D. AI Conversation Panel
แสดง:
- ข้อความจากผู้ใช้
- คำตอบของ AI
- ข้อความที่แปลงมาจากเสียง
- คำสั่งที่ AI ตีความ
- สถานะการดำเนินการ
- ผลการทำงานจากอุปกรณ์

ตัวอย่างบทสนทนา:
ผู้ใช้: "เปิดไฟห้องหลัก"
AI: "กำลังส่งคำสั่งเปิดไฟห้องหลัก"
ระบบ: "เปิดไฟสำเร็จ" เมื่อได้รับการยืนยันจากอุปกรณ์จริงเท่านั้น

### E. Smart Device Control
เริ่มต้นด้วยอุปกรณ์จริงหนึ่งชิ้น:
- ไฟห้องหลัก
- สถานะ On / Off
- Brightness Slider
- ค่าความสว่างเป็นเปอร์เซ็นต์
- สถานะการเชื่อมต่อ
- ปุ่มควบคุมด้วยตนเอง

เตรียมโครงสร้างให้เพิ่มพัดลมและอุปกรณ์อื่นได้ในอนาคต

การปรับความสว่างต้องสัมพันธ์กับวงจรหรี่ไฟที่รองรับจริง หากยังไม่เชื่อมฮาร์ดแวร์ให้ใช้ Mock Data และระบุว่าเป็นโหมดจำลอง

### F. System Activity Panel
แสดง:
- คำสั่งล่าสุด
- เวลาเรียกใช้คำสั่ง
- ผลการทำงาน
- สถานะการเชื่อมต่อ
- ข้อผิดพลาดและการแจ้งเตือน

## 4. Responsive Mobile Design

ออกแบบ Mobile UI แยกจาก Desktop อย่างเหมาะสม ไม่ใช่แค่ย่อทุกอย่างให้เล็กลง

บนมือถือ:
- ให้ AI Core และปุ่มสั่งงานอยู่ในตำแหน่งเข้าถึงง่าย
- มีปุ่มไมโครโฟนที่ชัดเจน
- มีช่องพิมพ์คำสั่ง
- มีการ์ดควบคุมไฟ
- แสดงสถานะอุปกรณ์และการแจ้งเตือน
- ใช้ Bottom Navigation หรือ Navigation ที่เหมาะสม
- รองรับจอแนวตั้งและขนาดหน้าจอหลายระดับ
- ใช้ Touch Target ที่เหมาะสม
- ไม่ให้แผงข้อมูลซ้อนทับกัน

## 5. AI Interaction States

กำหนด Visual State และ Animation ของแต่ละสถานะ:

1. IDLE — AI พร้อมรับคำสั่ง
2. LISTENING — กำลังรับเสียงจากไมโครโฟน
3. TRANSCRIBING — กำลังแปลงเสียงเป็นข้อความ
4. THINKING — LLM กำลังประมวลผล
5. EXECUTING — กำลังเรียก MCP Tool
6. WAITING_FOR_DEVICE — รอการตอบกลับจาก Arduino
7. SUCCESS — ได้รับการยืนยันว่าทำงานสำเร็จ
8. ERROR — คำสั่งล้มเหลว
9. DISCONNECTED — ระบบหรืออุปกรณ์ขาดการเชื่อมต่อ

แต่ละสถานะต้องมีข้อความ สี และแอนิเมชันที่แตกต่างกันอย่างเข้าใจง่าย

ต้องมีการจัดการกรณีไมโครโฟนไม่ได้รับอนุญาต ไม่มีอินเทอร์เน็ต AI ตอบช้า และ Arduino ไม่ตอบกลับ

## 6. Animation Direction

ออกแบบ Animation System แบบหลายชั้น เช่น:
- Slow Orbit Rotation
- Core Pulse
- Glow Breathing
- Audio Reactive Waveform
- Particle Drift
- Scanning Lines
- Data Stream
- Panel Entrance
- Status Transition
- Button Feedback
- Success / Error Feedback

กำหนดให้แต่ละเอฟเฟกต์มีวัตถุประสงค์ชัดเจน

หลีกเลี่ยงการสร้าง DOM จำนวนมากโดยไม่จำเป็น และหลีกเลี่ยงเอฟเฟกต์หนักที่ทำให้หน้าเว็บกระตุก

รองรับ prefers-reduced-motion และมีแนวทางลดเอฟเฟกต์สำหรับอุปกรณ์ประสิทธิภาพต่ำ

## 7. Technology Stack ที่เสนอ

ยังไม่ต้องเขียนโค้ด แต่ให้วางแผนโดยใช้แนวทางต่อไปนี้:

- Frontend: React + Vite + TypeScript
- Styling: Tailwind CSS
- Animation: CSS Animation และ Framer Motion
- Advanced 3D: Three.js เฉพาะเมื่อมีความจำเป็น
- Charts: Recharts หรือไลบรารีที่เหมาะสม
- Communication: HTTP API / WebSocket
- Backend: Python หรือ Node.js โดยเลือกจากความเหมาะสมกับ MCP และระบบที่มีอยู่

ก่อนเลือกไลบรารี ให้ตรวจสอบความเข้ากันได้และความจำเป็น ไม่เพิ่ม Dependencies โดยไม่มีเหตุผล

## 8. Architecture สำหรับ Smart Home AI

ระบบในอนาคตจะประกอบด้วย:

Mobile / Desktop Web App
→ Backend API
→ LLM
→ MCP Client
→ MCP Server
→ Device Controller
→ Arduino UNO Q
→ Hardware Driver
→ 12V DC Light

Backend ต้องเป็นตัวกลางในการตรวจสอบคำสั่งและจัดการความปลอดภัย

ห้ามให้ LLM สั่ง GPIO โดยตรง ทุกคำสั่งต้องผ่าน Tools ที่กำหนดไว้ล่วงหน้า เช่น:
- get_device_status
- turn_light_on
- turn_light_off
- set_brightness

ตรวจสอบค่า Input และขอบเขตคำสั่งทุกครั้ง

ห้ามแสดงผลว่าสำเร็จจนกว่าจะได้รับการยืนยันที่เหมาะสมจาก Controller หรืออุปกรณ์

สำหรับการควบคุมจากนอกบ้าน ต้องวางแผนการยืนยันตัวตนและการสื่อสารอย่างปลอดภัย ห้ามเปิด MCP Server หรือพอร์ตควบคุมอุปกรณ์ออกสู่อินเทอร์เน็ตโดยตรงโดยไม่มีระบบป้องกัน

## 9. ขั้นตอนที่ต้องทำในรอบนี้

รอบนี้ให้ทำเฉพาะการวางแผนและออกแบบ ห้ามสร้างโค้ด

ส่งผลลัพธ์ตามลำดับดังนี้:

1. วิเคราะห์คลิปและสรุป Design Direction
2. ระบุ Design Principles และ Visual Identity
3. สร้าง Sitemap ของระบบ
4. วาด Desktop Wireframe แบบ ASCII หรือ Diagram
5. วาด Mobile Wireframe แบบ ASCII หรือ Diagram
6. ระบุ Component Inventory ของแต่ละหน้าจอ
7. สร้างตาราง Animation Specification โดยระบุ State, Trigger, Effect และวัตถุประสงค์
8. สร้างตาราง UX Interaction Flow ตั้งแต่ผู้ใช้สั่งงานจนถึงอุปกรณ์ตอบกลับ
9. ออกแบบ Loading, Empty, Error และ Disconnected States
10. วางแผน Responsive Breakpoints
11. วางแผนโครงสร้าง Frontend Components และโฟลเดอร์ในอนาคต
12. วางแผนการเชื่อมต่อ Backend, LLM, MCP และ Arduino UNO Q
13. แบ่งการพัฒนาเป็น Milestones พร้อมเกณฑ์ตรวจรับ
14. สรุปคำถามที่จำเป็นต้องตอบก่อนเริ่มเขียนโค้ด

หากสามารถสร้าง Visual Prototype หรือ Design Board ได้ ให้เสนอหลังจากอธิบาย Wireframe แล้ว แต่ยังไม่ต้องเริ่มเขียนโปรแกรม

## 10. ข้อกำหนดด้านคุณภาพ

- ต้องออกแบบโดยคำนึงถึงการใช้งานจริง
- ห้ามเริ่มเขียนโค้ดก่อนส่งแผนให้ผมตรวจ
- ห้ามสร้างหน้าจอที่เต็มไปด้วยกราฟหรือตัวเลขที่ไม่มีความหมาย
- ห้ามใช้ข้อมูลจำลองปะปนกับสถานะจริงโดยไม่ระบุ
- ให้ความสำคัญกับความลื่นไหลและการตอบสนอง
- รองรับ Desktop และ Mobile
- ต้องมีแนวทางต่อยอดไปยังฮาร์ดแวร์จริง
- ใช้ภาษาไทยในการอธิบาย และใช้ชื่อ Component หรือศัพท์เทคนิคภาษาอังกฤษได้
- อธิบายเหตุผลในการเลือก Layout และเทคโนโลยี
- หากข้อมูลจากคลิปไม่เพียงพอ ให้ระบุข้อสมมติฐานอย่างชัดเจน

**เริ่มจากการวิเคราะห์คลิป วางแผน UX/UI และส่ง Blueprint ทั้งหมดให้ผมตรวจสอบก่อนเท่านั้น ห้ามเขียนโค้ดจนกว่าผมจะอนุมัติ**
